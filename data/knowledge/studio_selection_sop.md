# 目标

在不遗漏关键人物和关键瞬间的前提下，用可重复的标准完成技术淘汰、语义检索、
审美排序、连拍去重、人工复核和成品交付。

# 输入与目录

每个场次至少包含原始照片目录和对应的 `Previews` 目录。系统产出
`analysis_results.json`，并根据配置生成预览、分档结果和 Web Gallery。
导出时需要保持 Preview 与同名 RAW 的对应关系。

# 第一阶段：技术淘汰

优先排除以下照片：

- 严重失焦，主体没有任何可辨认清晰区域。
- 非创作意图的强烈运动模糊。
- 大面积不可恢复的过曝或欠曝。
- 主体被意外遮挡、截断或完全背对镜头。
- 测试片、地面、设备误触和明显无效帧。

边界案例不得仅凭单一指标自动删除。故意慢门、剪影、强颗粒和极端舞台灯光可能是
有效创作选择，应进入语义和人工复核。

# 第二阶段：语义与审美筛选

根据用户请求识别主体、动作、风格、平台和数量。常用审美维度包括：

- `moment_peak`：动作、表情和事件是否处于峰值。
- `atmosphere_impact`：现场感染力和环境关系。
- `light_color_character`：灯光、色彩和轮廓是否具有特点。
- `composition_framing`：主体位置、空间关系和裁切稳定性。
- `technical`：对焦、曝光、噪点和细节是否达到用途要求。
- `deliverable_subject`：主体是否完整、可识别并适合交付。

“张力”不是单一标签。默认以瞬间峰值、现场感染力、戏剧性光影和强构图进行组合排序，
再结合具体主体和发布平台复核。

# 第三阶段：连拍去重

同一动作序列中，优先保留：

1. 表情最完整的一帧。
2. 手、乐器和肢体位置最清楚的一帧。
3. 遮挡最少、构图最稳定的一帧。
4. 灯光状态最有辨识度的一帧。

如果多帧共同呈现动作变化，可以保留一个短序列；否则默认每个高度相似簇保留一张。

# 第四阶段：覆盖度检查

交付集合需要覆盖实际拍摄范围，不要求机械平均。检查项目包括：

- 主要艺人和乐手是否有代表照片。
- 特写、中景、全景和环境是否有节奏变化。
- 独奏、互动、观众和谢幕等关键事件是否覆盖。
- 是否因模型偏好而过度集中某种灯光、机位或人物。
- 是否存在同一场景重复过多、其他场景完全缺失的问题。

# 第五阶段：人工复核

摄影师在 Gallery 中检查 AI 推荐，并执行保留、拒绝和替换。反馈需要尽量具体：

- “太暗”对应曝光控制问题。
- “太糊”对应技术清晰度问题。
- “没张力”对应瞬间或情绪强度问题。
- “主体被挡”对应主体可交付性问题。

明确反馈通过 `record_selection_feedback` 保存，后续相似选片通过 Experience RAG
转换为最低质量门槛和排除项。历史经验不能覆盖本轮用户的明确要求。

# 交付前检查

- 文件数量和用户请求一致，或清楚说明不足原因。
- 文件名、Preview 和 RAW 一一对应。
- 没有重复帧、测试片或误选照片。
- 色彩空间、分辨率和导出格式符合客户约定。
- 版权、肖像、保密和发布范围已经确认。
- 保存交付清单、版本号和必要的修改记录。

# Agent 行为边界

- 当前场次检索使用 `gallery_search`。
- 历史场次检索使用 `archive_search`，返回结果不能直接当作当前场次文件导出。
- 不得编造不存在的照片、评分、人物身份或授权状态。
- 自动排序是候选建议，不替代摄影师对创作意图和权利风险的最终判断。
